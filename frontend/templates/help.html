STAGE 02

Reconciliation Decision Flowchart & 4-Pass Cascade

How the engine evaluates primary statement records against counterpart channels in sequence.

Primary & Counterpart Records Ingested Bank statements, gateway settlement feeds, order ledgers, and UPI registers
PASS 1 • EXACT RULE MATCHER UTR / RRN / Reference ID • Exact Amount Parity • Date Gap ≤ 3 Days

Exact Reference & Identifier Matcher

Pairs records with sanitized reference codes (UTR, Bank Ref, Bill No) and 100% amount parity.

YES (Matched) SETTLED / MATCHED

100% Exact Parity. Auto-committed to Reconciliation Store.

NO (Unmatched) Proceeds to Pass 2 ↓

No exact reference match found. Routing to 4-Factor Composite Scorer.

PASS 2 • COMPOSITE SCORER & 12D ML S = 0.40(ID) + 0.30(Amt) + 0.15(Date) + 0.15(Narr) • Weekend Adjusted

4-Factor Weighted Similarity Matrix

Evaluates multi-vector similarity across fuzzy IDs, date offsets, narration token overlap, and amount tolerance (≤ ₹1.00).

S ≥ 0.85 MATCHED

High-confidence score. Auto-approved match.

0.50 ≤ S < 0.85 SIMILAR

Potential match (minor variance or fuzzy text). Queued in Review Drawer.

S < 0.50 Proceeds to Pass 3 ↓

Low confidence score. Routing to Batch Fee Solver.

PASS 3 • SPLIT & MDR FEE SOLVER Net Payout = ∑ Gross Sales − Gateway MDR Fees − GST Taxes

1-to-N Batch Payout & MDR Fee Solver

Reconciles 1 lump-sum bank deposit against N individual order transactions minus gateway commission fees and taxes.

YES (Fee Parity Met) SETTLED

Batch payout fee equation balances. Auto-settled.

NO (Unbalanced) Proceeds to Pass 4 ↓

Fee equation fails to balance. Routing to Groq LLM Agent.

PASS 4 • GROQ LLM AGENT Structured JSON Context • Multi-Key Rotation (`GROQ_API_KEY`)

Groq LLM Ambiguous Match Resolver

Evaluates ambiguous candidate pairs using Groq API with multi-key failover and natural language audit explanations.

CONFIRMED MATCHED

AI verified match with natural language reasoning.

REJECTED UNMATCHED

Orphan discrepancy logged in Exception Ledger.

Forward Cash Forecaster & Liquidity Model

Projects 30-day liquid cash trajectories, estimates empirical settlement lags, and propagates beginning balance state.

14-DAY WMA & SEASONAL DECOMPOSITION

Weighted Moving Average Trend

Decomposes daily net inflows into trend level T(d) and 7-day weekly seasonal component S(d). Computes 30-day forward baseline cash trajectories with 1.5σ confidence bands.

Projected(t) = Trend_last + S(t mod 7) + Pending(t)
SETTLEMENT LAG ESTIMATOR

Channel Settlement Cycles

Evaluates historical channel lags to estimate future payout dates for open gateway batches. Applies T+2 for Razorpay, T+3 for Stripe/Cards, and T+0 for direct UPI.

Expected_Date = Batch_Date + Lag_Channel
BEGINNING BALANCE CASCADE

Cumulative Liquid Cash Progression

Anchors cumulative cash balances on the user-configured Beginning Balance (B₀). Updating beginning balance in the UI instantly recalculates Overview KPIs, Forecast curves, and PDF Reports.

C(d) = B₀ + ∑ Net_Cash_Flow(k)

STAGE 05

Complete Status Taxonomy Specification

Definitions, qualification criteria, and UI representations for all 4 reconciliation outcomes.

SETTLED 200_SETTLED

Primary Statement Reconciled

Match involves a Primary Statement record (Bank/Cash). Reconciled with zero amount delta or valid MDR fee equation.

  • Rule: Primary statement record involved
  • Parity: Exact reference or net batch payout fee parity
  • UI Action: Auto-committed to Settled Summary dashboard.
MATCHED 201_MATCHED

Counterpart-to-Counterpart Match

Match between two Counterpart statement sources (Gateway vs Order Book) or verified via ML/LLM model.

  • Rule: Both records from Counterpart sources
  • Score: Composite Score ≥ 0.85
  • UI Action: Displayed in main reconciliation table.
SIMILAR 300_SIMILAR

Potential Candidate Match

Candidate match identified with potential keyword or amount alignment, queued for human/LLM review.

  • Score Window: 0.50 ≤ Score < 0.85
  • Keyword Extraction: Highlights shared tokens
  • UI Action: Routed to candidate review drawer.
UNMATCHED 400_UNMATCHED

Exception Discrepancy / Open Item

Financial discrepancy failing all matching rules ($< 0.50$). Isolated into the Exception Ledger.

  • Score: < 0.50
  • Audit Action: Never force-matched
  • UI Action: Isolated into Exception Ledger with "Run LLM Match".
