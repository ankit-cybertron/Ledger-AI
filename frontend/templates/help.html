STAGE 03

Multi-Pass Rules & Mathematical Scoring Formulas

Deterministic mathematical rules execute first; machine learning heuristics execute second.

PASS 1 • EXACT RULE MATCH

Exact Identifier & Amount Parity

  • UTR / Order Match: Explicit reference code equality.
  • Amount Difference: Must equal exactly ₹0.00.
  • Date Window: Transaction gap ≤ 3 calendar days.
  • Outcome: Assigned SETTLED status immediately.
PASS 2 • COMPOSITE SCORING

4-Factor Weighted Similarity Matrix

Score = 0.40(ID) + 0.30(Amt) + 0.15(Date) + 0.15(Narr)
  • ID Weight (0.40): Levenshtein distance on partial reference keys.
  • Amount Weight (0.30): Exponential decay penalty on variance ≤ ₹1.00.
  • Date Weight (0.15): Day gap delta decay over 3-day max window.
  • Narration Weight (0.15): Shared keyword token matching.
PASS 3 • SPLIT & FEE SOLVER

1-to-N Batch Payout Fee Equation

Net Settlement = ∑ Gross Sales − Fees − Taxes
  • Multi-Order Consolidation: Matches bank payouts against multiple gateway orders.
  • Fee Deduction Verification: Deducts gateway commission & GST automatically.
  • Outcome: Assigned SETTLED status upon exact net parity.
STAGE 04

Groq LLM Ambiguous Matching Agent

Handles non-standard narrations, customer name variations, and ambiguous reference keys using high-speed Llama-3 inference.

Agent Trigger Conditions

The LLM agent is invoked automatically when candidate scores fall in the ambiguous range (0.60 ≤ Score < 0.85), or when a user clicks "Run LLM Match" in the Comparison Modal.

Structured JSON Input Context:

{
  "primary_record": {
    "id": "BNK-TXN-0004",
    "amount": 4999.00,
    "description": "CARD-SETL Meera Iyer"
  },
  "candidate_record": {
    "id": "PGREF202421",
    "amount": 5000.00,
    "fee": 1.00,
    "description": "Payment ORD8034 Meera Iyer"
  }
}

Structured Reasoning Output

The Groq LLM API returns JSON adhering to a strict response schema, including natural language audit explanation:

Recommendation: CONFIRMED
Confidence Score: 0.92 / 1.00
Audit Reasoning:

"The bank transaction 'CARD-SETL Meera Iyer' for ₹4,999.00 matches card payment PGREF202421 for ₹5,000.00 minus a ₹1.00 gateway processing fee. Customer name 'Meera Iyer' and transaction dates (1-day gap) align perfectly."

STAGE 05

Complete Status Taxonomy Specification

Definitions, qualification criteria, and UI representations for all 4 reconciliation outcomes.

SETTLED 100_SETTLED

Fully Reconciled & Balanced

100% mathematical parity. Reference match with zero amount delta or valid fee equation.

  • Score: 1.00 (Exact)
  • Amount Delta: Exactly ₹0.00
  • UI Action: Auto-committed to primary summary dashboard.
MATCHED 200_MATCHED

High-Confidence Pair

Passes composite scoring thresholds (≥ 0.85) or verified by Groq LLM match reasoning.

  • Score: ≥ 0.85
  • Tolerance: Variance ≤ ₹1.00
  • UI Action: Displayed in main reconciliation table.
SIMILAR 300_SIMILAR

Potential Candidate Match

Candidate matches in the moderate confidence band requiring human review or shared keyword audit.

  • Score: 0.50 ≤ Score < 0.85
  • Keywords: Shared customer tokens highlighted.
  • UI Action: Routed to "Find Similar Payments" drawer.
UNMATCHED 400_UNMATCHED

Exception Discrepancy

Orphaned entry unable to find any candidate match scoring above the 0.50 floor.

  • Score: < 0.50
  • Reason: Missing deposit, chargeback, or uncollected fee.
  • UI Action: Isolated into Exception Ledger table.
