Learn how Ledger AI ingests multi-format statements, maps data schemas, executes a deterministic 3-pass reconciliation cascade, and leverages Groq Llama-3 LLM reasoning for genuine ambiguities.

STAGE 01

Multi-Format Statement Ingestion Pipeline

From raw file upload (`.csv`, `.xlsx`, `.pdf`) to canonical normalized transaction models.

STEP 01

Multi-Format PDF & Table Extractor

Extracts CSV, Excel sheets, and PDF statement tables (ICICI, Razorpay, Payroll) with banner promotion and footer stripping.

STEP 02

Parenthetical & Currency Normalizer

Converts SBI parenthetical debits (1,234.56) to float -1234.56 and strips regional currency symbols.

STEP 03

Multi-Primary Bank & Header Mapper

Supports multi-primary bank pool loading (HDFC, SBI, ICICI) and maps headers via Levenshtein & dictionary alias algorithms.

STEP 04

Status Eligibility Filter

Excludes non-event status rows (FAILED, DECLINED, PENDING) before matching pool entry.

STEP 05

Cross-App Deduplication Hash

Generates cryptographic SHA-256 row fingerprints to resolve cross-app duplicate exports (GPay, PhonePe, Razorpay).

STAGE 03

Multi-Pass Rules & Mathematical Scoring Formulas

Deterministic mathematical rules execute first; machine learning heuristics execute second.

PASS 1 • EXACT RULE MATCH

Exact Identifier & Outbound Parity

  • UTR / Order Match: Explicit prefix-stripped reference code equality (1.00 confidence).
  • Vendor / Expense Debits: Bank debits matched to vendor register NEFT/RTGS lines.
  • Date Window: Business-day-aware settlement gap tolerance (1–4 days).
  • Outcome: Assigned SETTLED status immediately.
PASS 2 • COMPOSITE SCORING

4-Factor Weighted Similarity Matrix

Score = 0.40(ID) + 0.30(Amt) + 0.15(Date) + 0.15(Narr)
  • ID Weight (0.40): Substring and token matching on partial keys.
  • Amount Weight (0.30): MDR fee-aware calculation using 3.5% fee envelope.
  • Date Weight (0.15): Business day difference excluding weekends.
  • Narration Weight (0.15): Shared keyword token matching.
PASS 3 • SPLIT & FEE SOLVER

N:1 Batch Payout Fee Equation

Net Settlement = ∑ Gross Sales − MDR Fees − GST
  • Multi-Order Consolidation: Matches bank payouts against 58 Razorpay/UPI payments.
  • Fee Deduction Verification: Deducts gateway commission (1.8% + GST) automatically.
  • Outcome: Assigned SETTLED status upon exact net batch parity.
STAGE 04

Groq LLM Ambiguous Matching Agent

Handles non-standard narrations, customer name variations, and ambiguous reference keys using Llama-3 inference with API key rotation.

Agent Trigger Conditions

The LLM agent is invoked automatically when candidate scores fall in the ambiguous range (0.50 ≤ Score < 0.85), or when a user clicks "Run LLM Match" in the Candidate Modal. Rotates across Primary, Secondary, and Tertiary Groq API keys automatically.

Structured JSON Input Context:

{
  "primary_record": {
    "id": "BNK-TXN-0004",
    "amount": 4999.00,
    "description": "CARD-SETL Meera Iyer"
  },
  "candidate_record": {
    "id": "PGREF202421",
    "amount": 5000.00,
    "fee": 1.00,
    "description": "Payment ORD8034 Meera Iyer"
  }
}

Structured Reasoning Output

The Groq LLM API returns JSON adhering to a strict response schema, including natural language audit explanation:

Recommendation: CONFIRMED
Confidence Score: 0.92 / 1.00
Audit Reasoning:

"The bank transaction 'CARD-SETL Meera Iyer' for ₹4,999.00 matches card payment PGREF202421 for ₹5,000.00 minus a ₹1.00 gateway processing fee. Customer name 'Meera Iyer' and transaction dates (1-day gap) align perfectly."

STAGE 05

Complete Status Taxonomy Specification

Definitions, qualification criteria, and UI representations for all 4 reconciliation outcomes.

SETTLED 100_SETTLED

Fully Reconciled Bank Deposit

100% mathematical parity. Primary bank statement line matched with zero delta or valid MDR fee equation.

  • Score: 1.00 (Exact)
  • Amount Delta: Exactly ₹0.00 (or net MDR fee)
  • UI Action: Auto-committed to primary summary dashboard.
MATCHED 200_MATCHED

Counterpart / Order Book Pair

Counterpart-to-counterpart order cross-linking (Order Book ↔ UPI/card) or composite score ≥ 0.85.

  • Score: ≥ 0.85
  • Tolerance: Variance ≤ ₹1.00
  • UI Action: Displayed in main reconciliation table.
SIMILAR 300_SIMILAR

Potential Candidate Match

Candidate matches with digit transposition typos (₹47,097.63 vs ₹47,079.63) or moderate confidence.

  • Score: 0.50 ≤ Score < 0.85
  • Typo Guard: Surfaced for manual verification.
  • UI Action: Routed to "Find Similar Payments" drawer.
UNMATCHED 400_UNMATCHED

Exception Discrepancy / Open Item

True orphan exceptions (cash sales, unpaid orders, unknown bank debits), open refunds, or USD currency mismatch.

  • Score: < 0.50
  • Types: True orphan, open refund, currency mismatch.
  • UI Action: Isolated into Exception Ledger table.
